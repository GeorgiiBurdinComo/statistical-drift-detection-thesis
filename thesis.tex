\chapter{Introduction}

\section{Context and Motivation}
Industrial classification pipelines increasingly rely on Large Language Model (LLM) providers that expose their systems through application programming interfaces. In such settings, the deployed model can be viewed as a non-stationary black-box function $f_t(x)$ whose internal parameters and update schedule are controlled by the provider rather than by the user. As a result, the behaviour of the same API-accessible model may change over time even when the downstream task, the prompt, and the evaluation procedure remain fixed~\cite{chen2023chatgpt,tu2023chatlog,echterhoff2024muscle}.

The practical motivation for this thesis arises from the author's two-year work experience at \textbf{Gocomo GmbH}. In the company's social-media analytics workflow, LLMs are used in batch mode to determine whether a post is relevant to a specified campaign, brand, event, or other marketing entity. This is naturally formulated as a binary classification task. Because the volume of incoming content is large, manual verification is not scalable, and automated classification becomes a necessary operational component.

However, the use of external LLM APIs creates a reliability problem. A model that performs well during an initial benchmark may later degrade due to silent provider-side updates. In a business-critical pipeline, such degradation must be detected early. At the same time, repeated full-scale benchmarking on a large labelled dataset is costly. This creates a need for a monitoring methodology that is statistically informative, operationally feasible, and economically justified.
\section{Problem Statement}
This thesis addresses the problem of how to evaluate and monitor API-based LLM classifiers in a production environment where model behaviour may change over time. The central challenge is that the user does not control the underlying model updates, yet must still make reliable deployment decisions based on observed task performance.

More specifically, the problem consists of four interconnected parts:
\begin{enumerate}
    \item The social-media relevance detection task must be formalised in a way that permits consistent evaluation across models, prompts, and time points.
    \item Because repeated evaluation on the full reference benchmark is economically expensive, a smaller monitoring subset must be constructed without losing the ability to detect practically relevant performance changes.
    \item A statistical rule is required to distinguish variability in performance from genuine model drift.
    \item Once multiple candidate models are monitored, deployment decisions must account not only for predictive performance but also for inference cost.
\end{enumerate}

In addition, if a deployed model exhibits degraded performance, it is natural to ask whether this degradation can be mitigated without immediately replacing the model. This motivates the investigation of prompt optimisation as an adaptive mechanism within the monitoring framework.

Accordingly, the thesis does not study model drift merely as an observational phenomenon. Its objective is to develop a practically usable framework for benchmark design, drift-sensitive monitoring, cost-aware model selection, and post-drift adaptation for binary classification with black-box LLM APIs.
\section{Research Questions}
The problem stated above is investigated through the following research questions:

\begin{enumerate}
    \item[\textbf{RQ1:}] How can the campaign-relevance detection task be formally represented as a binary classification problem for non-stationary black-box LLM APIs?

    \item[\textbf{RQ2:}] How can a reduced monitoring subset be derived from a larger reference benchmark so that routine evaluation remains substantially cheaper while preserving sensitivity to model drift?

    \item[\textbf{RQ3:}] Which statistical criteria and alerting rules are appropriate for detecting practically significant performance degradation over time?

    \item[\textbf{RQ4:}] How should candidate models be compared and selected when deployment decisions depend on both predictive quality and inference cost?

    \item[\textbf{RQ5:}] To what extent can prompt optimisation improve or recover task performance after drift has been detected, and how can such optimisation be integrated into the monitoring loop?
\end{enumerate}

\chapter{Data and Evaluation Setup}

\section{Formal Problem Definition}
To evaluate model drift rigorously, we must first define the classification task within a probabilistic framework. Let $\mathcal{X} \subset \mathbb{R}^d$ denote the high-dimensional input space of social-media posts (comprising text, metadata, and visual features) and $\mathcal{Y} = \{0, 1\}$ the binary label space, where $1$ indicates relevance to a campaign. 

In the context of LLM-as-a-Service, the model is a non-stationary black box. We define the classifier as a function $f(x; \pi, \theta_t) \to \hat{y} \in \{0, 1\}$, where $\pi$ is a fixed prompt and $\theta_t$ represents the hidden, time-varying model weights. 

Under the zero-one loss function $\mathcal{L}(\hat{y}, y) = \mathbb{I}(\hat{y} \neq y)$, the \textbf{Expected Risk} (or true error rate) at time $t$ is:
\begin{equation}
    R_t(f) = \mathbb{E}_{(x,y) \sim P_t} [\mathbb{I}(f(x; \pi, \theta_t) \neq y)]
\end{equation}
Since the true data-generating distribution $P_t$ is unknown, we must estimate this risk empirically.

\section{The Reference Benchmark vs. Operational Constraints}
Let $\mathcal{D}_N$ be the reference benchmark consisting of $N = 1200$ manually labelled examples, establishing the ground truth. Evaluating all candidate models against $\mathcal{D}_N$ yields a highly precise empirical risk $\hat{R}_N$. 

However, running inference on $N=1200$ instances weekly across multiple candidate models is economically prohibitive. We require a monitoring subset $\mathcal{D}_n \subset \mathcal{D}_N$ of size $n \ll N$. The central mathematical challenge is to select $\mathcal{D}_n$ such that it remains highly sensitive to temporal shifts in the parameters $\theta_t$, despite the significantly reduced sample size.

\section{Informative Sampling via Model Disagreement}
A simple random sample (SRS) of size $n$ would yield an unbiased estimator of $R_t$. However, the vast majority of social-media posts are "easy" instances located far from the model's decision boundary, where the conditional probability $P(Y=1|X) \approx 1$ or $0$. These instances exhibit low prediction variance and are highly robust to small parameter shifts in $\theta_t$. 

To maximize the sensitivity of our monitoring subset, we abandon uniform sampling in favor of \textbf{Uncertainty Sampling}. We construct $\mathcal{D}_n$ exclusively from instances where an initial ensemble of distinct models $\mathcal{M} = \{f_1, f_2, \dots, f_K\}$ exhibited disagreement:
\begin{equation}
    \mathcal{D}_{n} = \{ x_i \in \mathcal{D}_{N} \mid \exists f_j, f_k \in \mathcal{M} : \hat{y}_{i,j} \neq \hat{y}_{i,k} \}
\end{equation}

To understand why this maximizes detection power, we must formalize the geometry of the classifier's decision space and prove that disagreement isolates instances of maximal statistical variance.

\subsection{Geometry of the Decision Boundary}
In modern representation learning, it is standard to assume the \emph{Manifold Hypothesis}: the tenet that nominally high-dimensional data are in fact concentrated near a lower-dimensional submanifold \cite{cayton2005,fefferman2016}. This assumption serves as a primary inductive bias for deep learning architectures \cite{bengio2013}, as it allows models to circumvent the curse of dimensionality by focusing on the intrinsic geometric structure of the data rather than the ambient space. 

\begin{assumption}[Data Manifold]
Let the input space $\mathcal{X} \subset \mathbb{R}^d$ be a smooth, compact Riemannian manifold.
\end{assumption}

For any ensemble $\mathcal{M}$, let $\bar{p}: \mathcal{X} \to [0, 1]$ be the continuous consensus probability function, where $\bar{p}(x)$ represents the ensemble's expected probability that $Y=1$.

\begin{definition}[Consensus Decision Boundary]
The decision boundary $\mathcal{B}$ of the ensemble is the pre-image of the classification threshold:
\begin{equation}
    \mathcal{B} = \bar{p}^{-1}(0.5) = \left\{ x \in \mathcal{X} \mid \bar{p}(x) = 0.5 \right\}
\end{equation}
\end{definition}

\begin{proposition}
If $0.5$ is a regular value of the function $\bar{p}$ (i.e., the gradient $\nabla \bar{p}(x) \neq 0$ for all $x \in \mathcal{B}$), then by the \textbf{Regular Level Set Theorem}, the decision boundary $\mathcal{B}$ is a smooth submanifold of $\mathcal{X}$ of codimension $1$.
\end{proposition}

This establishes $\mathcal{B}$ as a formal geometric hypersurface dividing the data manifold $\mathcal{X}$ into two distinct classification regions.

\subsection{Proof of Maximal Uncertainty via Disagreement}
We now prove that sampling instances where models disagree mathematically confines the sample to a tight neighborhood around the submanifold $\mathcal{B}$.

\begin{assumption}[Bounded Ensemble Divergence]
Assume the models in $\mathcal{M}$ represent competent classifiers approximating the same underlying logic, such that their individual scoring functions $p_m(x)$ diverge from the consensus $\bar{p}(x)$ by no more than $\epsilon$:
\begin{equation}
    \sup_{x \in \mathcal{X}} |p_m(x) - \bar{p}(x)| \leq \epsilon \quad \text{for all } m \in \{1, \dots, K\}
\end{equation}
\end{assumption}

\begin{proposition}[Disagreement Bounds Distance to $\mathcal{B}$]
If there exists a disagreement within the ensemble $\mathcal{M}$ for a given instance $x$ (i.e., $p_j(x) < 0.5$ and $p_k(x) \geq 0.5$), then the consensus probability $\bar{p}(x)$ is strictly bounded within an $\epsilon$-neighborhood of $0.5$.
\end{proposition}

\begin{proof}
Applying the bounded divergence assumption to the disagreeing models:
\begin{align}
    \bar{p}(x) - \epsilon &\leq p_j(x) < 0.5 \implies \bar{p}(x) < 0.5 + \epsilon \\
    \bar{p}(x) + \epsilon &\geq p_k(x) \geq 0.5 \implies \bar{p}(x) \geq 0.5 - \epsilon
\end{align}
Thus, it strictly follows that $\bar{p}(x) \in [0.5 - \epsilon,\ 0.5 + \epsilon]$.
\end{proof}

By geometrically isolating instances where models produce conflicting predictions, we are effectively sampling directly from the $\epsilon$-tube surrounding the submanifold $\mathcal{B}$. At the theoretical limit ($\epsilon \to 0$), the binary entropy $H(Y|X)$ reaches its global maximum of $1$ bit. The model is maximally uncertain, meaning the expected accuracy approaches random guessing ($A \approx 0.5$). 

This geometric isolation formalizes why disagreement sampling forces the evaluation subset into the \textbf{Maximum Variance} state for a Bernoulli process, which serves as the foundational assumption for determining the required sample size.

\section{Statistical Derivation of the Sample Size}
The decision to sample from the $\epsilon$-neighborhood of the decision boundary directly dictates the required sample size $n$. By forcing the expected accuracy toward $A = 0.5$, we deliberately subject our evaluation to the \textbf{Maximum Entropy} state. For a Bernoulli process, the variance $\sigma^2 = A(1-A)$ reaches its absolute maximum of $0.25$ exactly at $A=0.5$. 

NB! show disagreement of annotators


To determine $n$ under this worst-case variance, we must define the \textbf{Minimum Detectable Effect (MDE)} $\Delta$. In our production environment, human inter-annotator disagreement establishes an irreducible noise floor of $\epsilon_{noise} \approx 0.05$ ($5\%$). Any model drift smaller than $\epsilon_{noise}$ is statistically indistinguishable from background label noise. Thus, our monitoring system must have a margin of error strictly bounded by $\Delta = 0.05$.

We formalize this requirement using the margin of error for a one-sided hypothesis test (detecting degradation) at a significance level of $\alpha = 0.05$. Let $Z_{1-\alpha} \approx 1.645$ be the critical value from the standard normal distribution. The required sample size $n$ must satisfy:
\begin{equation}
    Z_{1-\alpha} \sqrt{\frac{A(1-A)}{n}} \le \Delta
\end{equation}

Substituting the maximum variance assumption $A(1-A) = 0.25$ and our noise floor $\Delta = 0.05$, we obtain:
\begin{equation}
    1.645 \sqrt{\frac{0.25}{n}} \le 0.05
\end{equation}
\begin{equation}
    \frac{0.8225}{\sqrt{n}} \le 0.05 \implies \sqrt{n} \ge 16.45
\end{equation}
\begin{equation}
    n \ge 270.6
\end{equation}

Voluntarly, the theoretically required sample size of $n \ge 271$ is rounded up to $n=300$. This calculation proves that $300$ is the strict mathematical minimum required to detect a $5\%$ model drift under the maximum variance conditions induced by our informative sampling strategy.

\section{The Role of Selection Bias and Importance Weighting}

Because $\mathcal{D}_{300}$ intentionally over-represents the manifold's decision boundary, the empirical accuracy calculated directly on this subset, $\hat{A}_n$, is a \textbf{biased estimator} of the global population accuracy $A_N$. Formally, $\mathbb{E}[\hat{A}_n] < A_N$, as the subset is deliberately composed of instances with high epistemic uncertainty.

In standard statistical evaluation, selection bias is viewed as a flaw to be corrected. In the context of our drift monitoring framework, however, this bias is an operational requirement. We track the biased metric $\hat{A}_n$ because it isolates the exact region of the input space where temporal parameter shifts ($\Delta \theta_t$) manifest most strongly, thereby maximizing the statistical power of the alerting rule.

Nevertheless, it is necessary to mathematically guarantee that this heavily biased subset remains formally linked to the underlying data-generating distribution, rather than being an arbitrary or disconnected sample. This rigorous link is established through the theory of \textbf{Importance Sampling} and the \textbf{Change of Measure}.

\subsection{The Horvitz--Thompson Link}
Let $S_i \in \{0, 1\}$ be an indicator variable for the inclusion of the $i$-th reference instance in the monitoring subset, with probability $q_i = P(S_i = 1 \mid \text{disagreement})$. The global accuracy $A_N$ can be theoretically recovered from the biased sample using the \textbf{Horvitz--Thompson (HT) estimator}:
\begin{equation}
    \hat{A}_{HT} = \frac{1}{N} \sum_{i=1}^{N} \frac{S_i \cdot \mathbb{I}(\hat{y}_i = y_i)}{q_i} = \frac{1}{N} \sum_{i \in \mathcal{D}_n} \frac{\mathbb{I}(\hat{y}_i = y_i)}{q_i}
\end{equation}

Here, the inverse probability $1/q_i$ acts as an importance weight (or Radon--Nikodym derivative) that maps the biased sampling measure back to the uniform population measure.

\begin{proof}[Proof of Unbiasedness]
To prove that $\hat{A}_{HT}$ correctly recovers the global accuracy, we take its expectation over the sampling design:
\begin{equation}
    \mathbb{E} [\hat{A}_{HT}] = \mathbb{E} \left[ \frac{1}{N} \sum_{i=1}^{N} \frac{S_i \cdot \mathbb{I}(\hat{y}_i = y_i)}{q_i} \right]
\end{equation}
By the linearity of expectation, and noting that the true labels and model predictions at a fixed time $t$ are deterministic with respect to the sampling mechanism:
\begin{equation}
    \mathbb{E} [\hat{A}_{HT}] = \frac{1}{N} \sum_{i=1}^{N} \frac{\mathbb{I}(\hat{y}_i = y_i)}{q_i} \mathbb{E}[S_i]
\end{equation}
Since $S_i$ is a Bernoulli random variable, its expected value is exactly its probability of occurrence, $\mathbb{E}[S_i] = q_i$. Substituting this yields:
\begin{equation}
    \mathbb{E} [\hat{A}_{HT}] = \frac{1}{N} \sum_{i=1}^{N} \frac{\mathbb{I}(\hat{y}_i = y_i)}{q_i} \cdot q_i = \frac{1}{N} \sum_{i=1}^{N} \mathbb{I}(\hat{y}_i = y_i) = A_N
\end{equation}
\end{proof}

\subsection{Operational Utility: Signal Amplification}
The proof above confirms that $\mathcal{D}_{300}$ is a statistically valid basis for inference, as it remains anchored to the reference population through the HT estimator. However, within the operational monitoring loop, we deliberately report the raw empirical accuracy $\hat{A}_n$ rather than the unbiased estimate $\hat{A}_{\mathrm{HT}}$. 

The rationale for this choice is rooted in \textbf{Signal-to-Noise Ratio (SNR) optimization}. Applying the importance weights $1/q_i$ would mathematically suppress the frequency of errors occurring at the decision boundary, effectively "smoothing" the data to reconstruct the global mean. While this is desirable for population estimation, it is counter-productive for \textbf{anomaly detection}. By utilizing the raw biased metric, we maintain the magnification of errors where the model is most unstable. Thus, $\hat{A}_n$ functions as a high-gain monitoring signal that provides a leading indicator of model drift, while the HT-framework provides the necessary theoretical guarantee that this signal is a rigorous and mathematically reversible projection of the global performance.

\chapter{Drift Monitoring and Model Selection Methodology}

\section{Formalisation of Temporal Evaluation}

Let $t \in \{1, \dots, T\}$ represent discrete evaluation intervals, for example weekly batch runs. At each time point $t$, a deployed model $m$ is evaluated on the same fixed monitoring subset $\mathcal{D}_{300} = \{(x_i,y_i)\}_{i=1}^{300}$. The key idea of this setup is that temporal changes in model behaviour should be measured on a constant reference set rather than on newly sampled data, so that differences across time can be attributed to model behaviour rather than to changes in the evaluation sample.

For each instance $x_i \in \mathcal{D}_{300}$, let
\begin{equation}
\hat{y}_{i,t} \in \{0,1\}
\end{equation}
denote the model prediction at time $t$. Since the true label $y_i$ is fixed, the correctness of the prediction at time $t$ can be represented by the binary indicator
\begin{equation}
E_{i,t} = \mathbb{I}(\hat{y}_{i,t} = y_i),
\end{equation}
where $\mathbb{I}(\cdot)$ is the indicator function. Thus, $E_{i,t}=1$ means that the model classified instance $i$ correctly at time $t$, whereas $E_{i,t}=0$ means that it made an error.

Using these indicators, the empirical accuracy of the model at time $t$ on the monitoring subset is
\begin{equation}
\hat{A}_t = \frac{1}{300}\sum_{i=1}^{300} E_{i,t}.
\end{equation}
This quantity is the fraction of correctly classified instances in the monitoring run. It provides a natural summary of aggregate predictive performance, but on its own it is not sufficient for rigorous drift detection.

The reason is that the sequence $(\hat{A}_t)_{t=1}^T$ is obtained by repeatedly evaluating the \emph{same} instances. Therefore, the empirical accuracies $\hat{A}_{t_1}$ and $\hat{A}_{t_2}$ are not independent sample proportions. A standard two-sample comparison such as the two-proportion $Z$-test would incorrectly treat the observations as independent and would therefore overestimate the sampling variance. In the present setting, the dependence structure must be taken into account explicitly. This motivates the use of a paired test based on per-instance changes in correctness.

\section{Statistical Drift Detection via McNemar's Test}

To formally detect temporal drift, it is more informative to analyse \emph{which instances changed status} than to compare marginal accuracies alone. In other words, the relevant signal is not simply whether the accuracy has changed, but whether instances that were previously correct have become incorrect, or vice versa.

\subsection{The Contingency Table}

For this purpose, the correctness indicators at two time points $t_1$ and $t_2$ are compared instance by instance. Each example in the monitoring subset falls into one of four categories:
\begin{itemize}
    \item correct at both times,
    \item correct at $t_1$ but incorrect at $t_2$,
    \item incorrect at $t_1$ but correct at $t_2$,
    \item incorrect at both times.
\end{itemize}

Aggregating these outcomes across all $n=300$ monitored instances yields the paired $2\times2$ contingency table for $(t_1, t_2)$. The corresponding cell counts can be written directly inside the table as
\begin{table}[h]
    \centering
    \caption{Paired $2\times2$ contingency table for correctness at times $t_1$ and $t_2$.}
    \label{tab:mcnemar_contingency}
    \begin{tabular}{c|p{0.35\textwidth}p{0.35\textwidth}}
        & \centering $E_{i,t_2}=1$ & \centering $E_{i,t_2}=0$ \tabularnewline
        \hline
        $E_{i,t_1}=1$ 
            & \centering $\displaystyle a = \sum_{i=1}^{300} \mathbb{I}(E_{i,t_1}=1,\; E_{i,t_2}=1)$ 
            & \centering $\displaystyle b = \sum_{i=1}^{300} \mathbb{I}(E_{i,t_1}=1,\; E_{i,t_2}=0)$ \tabularnewline
        $E_{i,t_1}=0$ 
            & \centering $\displaystyle c = \sum_{i=1}^{300} \mathbb{I}(E_{i,t_1}=0,\; E_{i,t_2}=1)$ 
            & \centering $\displaystyle d = \sum_{i=1}^{300} \mathbb{I}(E_{i,t_1}=0,\; E_{i,t_2}=0)$ \tabularnewline
    \end{tabular}
\end{table}

These four counts partition the monitoring subset, so that
\begin{equation}
a+b+c+d = 300.
\end{equation}

The interpretation of the cells is as follows:
\begin{itemize}
    \item $a$: instances classified correctly at both time points,
    \item $b$: instances that were correct at $t_1$ but became incorrect at $t_2$,
    \item $c$: instances that were incorrect at $t_1$ but became correct at $t_2$,
    \item $d$: instances classified incorrectly at both time points.
\end{itemize}

From the perspective of drift detection, the concordant counts $a$ and $d$ are not informative about temporal change, because they correspond to cases where the model's behaviour did not change. The evidence for drift is therefore concentrated in the discordant counts $b$ and $c$. In particular, $b$ captures regressions, whereas $c$ captures improvements.

This decomposition also clarifies the relation between paired comparisons and aggregate accuracy at the two time points. Since
\begin{equation}
\hat{A}_{t_1} = \frac{a+b}{300}
\qquad\text{and}\qquad
\hat{A}_{t_2} = \frac{a+c}{300},
\end{equation}
it follows that
\begin{equation}
\hat{A}_{t_2} - \hat{A}_{t_1} = \frac{c-b}{300}.
\end{equation}
Hence, the change in accuracy is determined entirely by the imbalance between regressions and improvements. McNemar's test exploits exactly this structure.

\subsection{The Test Statistic and Alerting Rule}

The null hypothesis of McNemar's test states that the probability of a regression equals the probability of an improvement:
\begin{equation}
H_0: p_b = p_c.
\end{equation}
Under this null hypothesis, the model is equally likely to lose correctness on an instance as it is to gain correctness on another instance, which corresponds to the absence of systematic drift.

Since the operational concern  is degradation, the relevant one-sided alternative is
\begin{equation}
H_a: p_b > p_c.
\end{equation}
This means that the model breaks more previously correct cases than it repairs previously incorrect ones.

To test this hypothesis, McNemar's statistic with continuity correction is used:
\begin{equation}
\chi^2 = \frac{(|b-c|-1)^2}{b+c}.
\end{equation}
The numerator measures the imbalance between regressions and improvements, while the denominator normalises this imbalance by the total number of changed cases. The subtraction of $1$ is the continuity correction, which is commonly used to make the large-sample chi-square approximation more conservative for finite samples.

The test statistic is approximately $\chi^2$-distributed with one degree of freedom when the number of discordant pairs is sufficiently large. Operationally, the monitoring pipeline raises a \textbf{Statistical Drift Alert} at time $t$ if both of the following conditions hold:
\begin{enumerate}
    \item \textbf{Directionality:} $b>c$, meaning that the model has deteriorated on more instances than it has improved.
    \item \textbf{Significance:} the corresponding $p$-value is below the chosen threshold $\alpha=0.05$.
\end{enumerate}
The directionality condition is important because statistical significance alone does not distinguish between degradation and improvement. By requiring both $b>c$ and $p<0.05$, the alerting rule is aligned with the practical objective of detecting harmful drift rather than any change whatsoever.

\section{Cost-Aware Model Selection}

Once performance has been measured, model selection must take into account not only predictive quality but also operational cost. In real deployments, a model that is slightly more accurate may still be unattractive if it is substantially more expensive to run at scale.

Let
\begin{equation}
A_t(m)
\end{equation}
denote the empirical accuracy of model $m \in \mathcal{M}$ at time $t$, and let
\begin{equation}
C_t(m)
\end{equation}
denote its average inference cost, measured in USD per 1 requests. The goal is to compare candidate models using a criterion that balances these two dimensions.

\subsection{The Deployment Utility Function}

To formalise this trade-off, define the deployment utility
\begin{equation}
U_t(m) = A_t(m) - \lambda \log\!\bigl(1 + C_t(m)\bigr),
\end{equation}
where $\lambda \ge 0$ is a business-defined cost sensitivity parameter.

The first term, $A_t(m)$, rewards predictive performance. The second term penalises operational cost. The parameter $\lambda$ controls how strongly cost influences the final decision:
\begin{itemize}
    \item if $\lambda = 0$, then
    \begin{equation}
    U_t(m)=A_t(m),
    \end{equation}
    so model selection is based purely on accuracy;
    \item if $\lambda > 0$, cost is explicitly incorporated into the deployment decision.
\end{itemize}

The logarithmic form of the penalty was chosen during a group workshop, where the value of $\lambda$ was set to $10$ to reflect the team's consensus on cost sensitivity in deployment scenarios. Unlike a linear penalty, the logarithmic option introduces diminishing marginal sensitivity to cost: a move from a very cheap to a moderately priced model is penalized more heavily than the same absolute cost increase at higher price levels, which better matches business intuition that value does not decrease linearly with API cost.

Figure~\ref{fig:utility-overview} shows the Streamlit view of the deployment utility definition and controls. Figures~\ref{fig:utility-table-lambda10}--\ref{fig:utility-vs-lambda-highlight} then illustrate the concrete per-model utilities and the behaviour of $U_t(m)$ as $\lambda$ varies.

\subsection{Decision Logic for Pipeline Adaptation}

The monitoring architecture follows a simple decision process after each batch evaluation:
\begin{enumerate}
    \item \textbf{Monitor:} compute the paired drift statistic for the currently deployed model $m_{\mathrm{curr}}$ by comparing its correctness on $\mathcal{D}_{300}$ at time $t$ against the chosen baseline time point.
    \item \textbf{Detect:} if the McNemar test indicates significant degradation, that is, if $b>c$ and $p<0.05$, register a drift event.
    \item \textbf{Act:} evaluate the deployment utility $U_t(m)$ for all available candidate models and select
    \begin{equation}
    m_t^\star \in \arg\max_{m\in\mathcal{M}} U_t(m).
    \end{equation}
\end{enumerate}

Thus, the selected deployment model is the one that maximises the joint accuracy--cost criterion at time $t$. If no available fallback model yields a satisfactory utility level, the system initiates the prompt optimisation loop described in Chapter~4. In that case, adaptation is attempted first at the prompt level, without replacing the underlying model API.

Overall, this methodology separates the monitoring problem into two layers. First, McNemar's test determines whether a meaningful temporal degradation has occurred. Second, the utility function
\begin{equation}
U_t(m)
\end{equation}
determines which model is most attractive from the deployment perspective once both predictive quality and cost are taken into account.

\chapter{Prompt Optimisation as an Adaptive Mechanism}
\section{Prompt Optimisation Problem Formulation}

Let $\mathcal{X}$ denote the input space and $\mathcal{Y}=\{0,1\}$ the set of binary labels. At time $t$, an external API-based large language model is represented by a stochastic predictor
\begin{equation}
    f_t(\,\cdot\,;\Pi) : \mathcal{X} \to \mathcal{Y},
\end{equation}
where $\Pi \in \mathcal{P}$ is a prompt from a discrete prompt space $\mathcal{P}$. The index $t$ reflects possible model drift over time: even for the same prompt $\Pi$, the conditional behaviour of the API model may change.

Let $P_t$ denote the joint distribution of $(X,Y)$ at time $t$. For a given loss function $\ell:\mathcal{Y}\times\mathcal{Y}\to\mathbb{R}_+$, the population risk of prompt $\Pi$ at time $t$ is
\begin{equation}
    R_t(\Pi) = \mathbb{E}_{(X,Y)\sim P_t}\bigl[\ell(f_t(X;\Pi),Y)\bigr].
\end{equation}
Equivalently, for a utility or score function $u$, one may consider the population utility
\begin{equation}
    U_t(\Pi) = \mathbb{E}_{(X,Y)\sim P_t}\bigl[u(f_t(X;\Pi),Y)\bigr].
\end{equation}
For binary classification, a natural choice is
\begin{equation}
    u(f_t(X;\Pi),Y)=\mathbf{1}\{f_t(X;\Pi)=Y\},
\end{equation}
so that $U_t(\Pi)$ coincides with accuracy.

The prompt optimisation problem at time $t$ is therefore
\begin{equation}
    \Pi_t^\star \in \arg\max_{\Pi\in\mathcal{P}} U_t(\Pi),
\end{equation}
or equivalently,
\begin{equation}
    \Pi_t^\star \in \arg\min_{\Pi\in\mathcal{P}} R_t(\Pi).
\end{equation}

Since $P_t$ is unknown, optimisation must be carried out using a finite labelled optimisation set
\begin{equation}
    \mathcal{D}_t = \{(x_i,y_i)\}_{i=1}^{n_t}.
\end{equation}
The empirical utility is
\begin{equation}
    \widehat{U}_t(\Pi)=\frac{1}{n_t}\sum_{i=1}^{n_t} s_i(\Pi),
\end{equation}
where
\begin{equation}
    s_i(\Pi)=u(f_t(x_i;\Pi),y_i).
\end{equation}
In the simplest case,
\begin{equation}
    s_i(\Pi)=\mathbf{1}\{f_t(x_i;\Pi)=y_i\}.
\end{equation}

Hence, the empirical prompt optimisation problem becomes
\begin{equation}
    \widehat{\Pi}_t \in \arg\max_{\Pi\in\mathcal{P}} \widehat{U}_t(\Pi).
\end{equation}

In this thesis, prompt optimisation is treated as a black-box optimisation problem over a discrete, non-smooth search space. No gradient information with respect to prompt text is assumed to be available. Instead, optimisation is performed by iteratively generating and evaluating candidate prompts.

To account for temporal model drift, one may also define the robust objective over a monitoring horizon $t\in\{1,\dots,T\}$:
\begin{equation}
    \Pi^\star_{\mathrm{rob}} \in \arg\max_{\Pi\in\mathcal{P}} \sum_{t=1}^{T} w_t U_t(\Pi),
\end{equation}
where $w_t\ge 0$ and $\sum_{t=1}^{T}w_t=1$ are time weights. This formulation expresses the fact that a prompt can be evaluated not only by its instantaneous performance but also by its stability under drift.

\section{Overview of Prompt Optimisation Strategies}

Given the black-box nature of $f_t(\cdot;\Pi)$ and the discrete space $\mathcal{P}$, most practically usable methods fall into a small number of families:
\begin{itemize}
    \item \textbf{Manual heuristic search:} human-designed variants $\Pi^{(1)}, \Pi^{(2)}, \dots$ evaluated on $\mathcal{D}_t$.
    \item \textbf{Bandit \& Bayesian optimisation:} treating prompts as arms in a multi-armed bandit with rewards $s_i(\Pi)$.
    \item \textbf{Local search / hill-climbing:} iteratively editing a single prompt and accepting only improving variants.
    \item \textbf{Evolutionary methods:} maintaining a population of prompts and applying mutation / selection; the GEPA method belongs to this class.
\end{itemize}

Formally, all of these can be written as stochastic optimisation algorithms that generate a sequence of prompts
\[
    \Pi^{(0)}, \Pi^{(1)}, \dots, \Pi^{(k)}, \dots
\]
and are allowed to query $f_t(\cdot;\Pi^{(k)})$ on instances from $\mathcal{D}_t$ in order to estimate $\widehat{U}_t(\Pi^{(k)})$. The algorithms differ in how they trade off \emph{exploration} of new parts of $\mathcal{P}$ against \emph{exploitation} of currently good prompts.

\subsection{Heuristic and Local Search}

In its simplest form, a local search method starts from an initial prompt $\Pi^{(0)}$ and repeatedly proposes a neighbour $\widetilde{\Pi}$ (for example, by editing task instructions or adding examples). If $\widehat{U}_t(\widetilde{\Pi}) \geq \widehat{U}_t(\Pi^{(k)})$ the algorithm moves to $\Pi^{(k+1)} := \widetilde{\Pi}$; otherwise it stays put.

This defines a Markov chain on $\mathcal{P}$ whose absorbing states are precisely the local optima:
\begin{equation}
    \Pi \text{ is a local optimum } \iff \widehat{U}_t(\Pi') \le \widehat{U}_t(\Pi)\ \ \forall \Pi' \in \mathcal{N}(\Pi),
\end{equation}
where $\mathcal{N}(\Pi)$ is the chosen neighbourhood (e.g.\ all prompts reachable by a single edit). Under a finite state space and a neighbourhood that is symmetric and irreducible, standard arguments from Markov chain theory imply that the chain will almost surely hit a local optimum in finitely many steps. However, there is no guarantee that this local optimum coincides with the global maximiser $\widehat{\Pi}_t$.

\subsection{Bandit-Based Prompt Selection}

An alternative view is to treat each prompt as an arm in a stochastic bandit. At round $k$, the optimiser chooses a prompt $\Pi^{(k)}$ and observes a random reward
\[
    R^{(k)} = s_{i_k}(\Pi^{(k)}),
\]
where $i_k$ indexes either a fresh example from the underlying stream or an element of $\mathcal{D}_t$ chosen according to some policy. Writing
\[
    \mu(\Pi) := \mathbb{E}[s_i(\Pi)],
\]
the aim is to minimise the cumulative regret
\begin{equation}
    \mathcal{R}_K = \sum_{k=1}^{K} \bigl(\mu(\Pi^\star) - \mu(\Pi^{(k)})\bigr).
\end{equation}

Classical algorithms such as UCB or Thompson sampling guarantee sublinear regret $\mathcal{R}_K = \mathcal{O}(\log K)$ when $\mathcal{P}$ is finite and rewards are bounded~\cite{lattimoreSzepesvari2020bandit}. As a consequence, the fraction of suboptimal prompt selections goes to zero:
\begin{equation}
    \frac{1}{K} \sum_{k=1}^{K} \mathbf{1}\{\Pi^{(k)} \neq \Pi^\star\} \xrightarrow[K\to\infty]{} 0.
\end{equation}
This provides a clean theoretical justification for bandit-style prompt selection when the set of candidate prompts is fixed a priori.

\subsection{Evolutionary and Population-Based Methods}

Population-based methods maintain a set of prompts
\[
    \mathcal{P}^{(k)}_{\mathrm{pop}} = \{\Pi^{(k)}_1,\dots,\Pi^{(k)}_M\}
\]
at iteration $k$, together with empirical utilities $\widehat{U}_t(\Pi^{(k)}_j)$. New candidates are generated by stochastic transformations (``mutations'') of the current population, and a selection rule decides which prompts survive to the next generation.

In the context of this thesis, we make this population-level view explicit by working with per-instance score vectors
\begin{equation}
    \bm{s}(\Pi) = \bigl(s_1(\Pi),\dots,s_{n_t}(\Pi)\bigr) \in \{0,1\}^{n_t}.
\end{equation}
This finer-grained representation allows us to reason not only about scalar utilities $\widehat{U}_t(\Pi)$ but also about the distribution of errors across $\mathcal{D}_t$.

\section{Theoretical Comparison of Strategies}

From the perspective of the objective $\widehat{U}_t(\Pi)$, the main differences between the strategies above can be summarised as follows:
\begin{itemize}
    \item Local search methods are cheap and exploitative but can become trapped in poor local optima.
    \item Bandit methods enjoy finite-time regret bounds when the prompt set is fixed but do not, by themselves, propose new prompts.
    \item Evolutionary methods naturally accommodate an open-ended search space where prompts are created on the fly but typically lack closed-form regret guarantees.
\end{itemize}

We now record two simple propositions that formalise properties used later in the design of the GEPA algorithm.

\begin{proposition}[Unbiasedness of Empirical Utility]
For any fixed prompt $\Pi$ and i.i.d.\ sample $\mathcal{D}_t = \{(x_i,y_i)\}_{i=1}^{n_t}$ from $P_t$, the empirical utility $\widehat{U}_t(\Pi)$ is an unbiased estimator of $U_t(\Pi)$:
\begin{equation}
    \mathbb{E}_{\mathcal{D}_t}\bigl[\widehat{U}_t(\Pi)\bigr] = U_t(\Pi).
\end{equation}
\end{proposition}
\begin{proof}
By definition,
\[
    \widehat{U}_t(\Pi) = \frac{1}{n_t}\sum_{i=1}^{n_t} s_i(\Pi),
\]
where $s_i(\Pi) = u(f_t(x_i;\Pi),y_i)$ and $(x_i,y_i)\sim P_t$ i.i.d. Taking expectations and using linearity,
\[
    \mathbb{E}_{\mathcal{D}_t}\bigl[\widehat{U}_t(\Pi)\bigr]
    = \frac{1}{n_t}\sum_{i=1}^{n_t} \mathbb{E}_{(X,Y)\sim P_t}\bigl[u(f_t(X;\Pi),Y)\bigr]
    = U_t(\Pi).
\]
\end{proof}

This proposition justifies using $\widehat{U}_t(\Pi)$ as the scalar fitness signal for all optimisation methods considered.

\begin{proposition}[Monotone Improvement under Exact Comparison]
Suppose a local search or evolutionary algorithm accepts a new prompt $\widetilde{\Pi}$ in place of $\Pi$ only if $\widehat{U}_t(\widetilde{\Pi}) \ge \widehat{U}_t(\Pi)$, with strict inequality for at least one accepted move. Then along any realised optimisation trajectory the sequence of empirical utilities is monotonically non-decreasing and can increase at most $\mathcal{O}(n_t)$ times by at least $1/n_t$ before reaching an empirical local optimum.
\end{proposition}
\begin{proof}
Each acceptance step enforces
\[
    \widehat{U}_t(\Pi^{(k+1)}) \ge \widehat{U}_t(\Pi^{(k)}),
\]
so the sequence is non-decreasing. Because $\widehat{U}_t(\Pi)\in\{0,1/n_t,\dots,1\}$, any strict improvement is at least $1/n_t$, and there are at most $n_t$ such distinct increases before the sequence saturates at $1$. Once no neighbour or mutation yields a strictly larger empirical utility, the algorithm has reached a local optimum with respect to the underlying move set.
\end{proof}

In practice, stochasticity of the API responses and finite evaluation budgets complicate these guarantees, but the monotonicity argument still motivates using empirical utility as the primary selection criterion in our population-based search.

\section{Integrating Optimisation into the Monitoring Loop}
When a deployed model triggers a drift alert ($D_t < -\tau_{\mathrm{drift}}$), switching to a more expensive model is not the only recourse. We can attempt to recover performance via prompt optimisation by explicitly optimising $\widehat{U}_t(\Pi)$ (or its robust counterpart $\sum_{t} w_t U_t(\Pi)$) over $\mathcal{P}$, subject to the operational constraints of the monitoring pipeline.

\section{Pareto-Based Prompt Search (GEPA)}
We utilize a reflective evolutionary method (GEPA)~\cite{gepa2025} for prompt adaptation. Because prompt space is discrete and non-convex, greedy selection often fails. Instead, we maintain a candidate pool of prompts and evaluate their per-instance score vectors $\bm{s}(\Pi) = (s_1(\Pi), \dots, s_n(\Pi))$. 

We retain prompts based on Pareto dominance to preserve search diversity. A prompt $\Pi^{(a)}$ dominates $\Pi^{(b)}$ if it performs at least as well on all instances and strictly better on at least one. By mutating prompts on the Pareto frontier using natural-language reflections from execution traces, we can systematically search for a prompt $\Pi^\star$ that maximizes $U_t(m)$ without altering the underlying API model.

\section{Dataset Storage and Trace Logging}
\label{sec:dataset-storage}

All labels and input features for the campaign relevance task are stored in Langfuse as a dedicated dataset.
Each row represents a single influencer post with a stable \texttt{custom\_id}, campaign brief, caption, optional image references, and a boolean \texttt{campaign\_relevant} label.
During evaluation, each model call is recorded as a Langfuse trace whose metadata includes the \texttt{custom\_id}, model name, provider, run identifier, latency, and token usage.
This makes it possible to reconstruct historical evaluations and to filter traces by dataset version, model, or time window when analysing drift.

\section{Batch Evaluation Process}
\label{sec:batch-process}

Batch runs are orchestrated by \texttt{run\_eval.py}, which:
\begin{enumerate}
    \item Loads an evaluation subset via \texttt{load\_dataset\_rows}, either directly from Langfuse or from a CSV export (e.g.\ the disagreement subset).
    \item Applies a shared prompt template to produce a normalised conversational payload (system + user messages) per example.
    \item Calls provider-specific helpers (\texttt{batch\_openai.py}, \texttt{batch\_gemini.py}, \texttt{batch\_claude.py}) that write JSONL request files and submit batch jobs.
    \item Writes a manifest \texttt{data/batch\_ids.json} listing all submitted batch IDs, models, and providers.
\end{enumerate}
GitHub Actions workflows schedule and execute this pipeline: they trigger batch submission, poll job status until completion, and then run the ingestion scripts (\texttt{poll\_and\_ingest.py}, \texttt{ingest.py}) that attach responses to the correct traces in Langfuse.

\section{Interaction with LLM APIs}
\label{sec:llm-api-interaction}

All models are queried via provider-native batch APIs, but the logical payload is always the same: a schema-constrained campaign relevance call built from one labeled example.
Concretely:
\begin{itemize}
    \item \textbf{OpenAI} (\texttt{batch\_openai.py}): writes JSONL lines of the form \{\texttt{custom\_id}, \texttt{method="POST"}, \texttt{url="/v1/responses"}, \texttt{body}\} and submits the file to the OpenAI Batch API with \texttt{endpoint="/v1/responses"}.
    \item \textbf{Gemini} (\texttt{batch\_gemini.py}): writes JSONL lines with a \texttt{request} object (contents, optional \texttt{systemInstruction}, \texttt{generationConfig}) and uploads the file to the Google GenAI batch API via \texttt{client.batches.create(model=..., src=...)}.
    \item \textbf{Claude} (\texttt{batch\_claude.py}): builds an in-memory list of \{\texttt{custom\_id}, \texttt{params}\} records and passes it directly to the Anthropic Messages Batches API via \texttt{client.messages.batches.create(requests=...)}; the streamed batch results are later normalised into JSONL by \texttt{download\_claude\_batch\_results}.
\end{itemize}
In all three cases, the underlying request encodes:
\begin{itemize}

\section{Metrics Collection and Monitoring Dashboard}
\label{sec:metrics-dashboard}

The monitoring stack exposes exactly two core metrics: \textbf{classification accuracy} on the monitoring subset and \textbf{inference cost} per model.

Ingestion is handled by the script \texttt{ingest.py}, which processes each batch output file as follows:
\begin{enumerate}
    \item Parse each JSONL line and normalise the provider response (OpenAI, Gemini, Claude) into a common structure.
    \item Extract the boolean \texttt{campaign\_relevant} prediction from the model output.
    \item Look up the ground-truth label for the corresponding \texttt{custom\_id} from Langfuse or a CSV export.
    \item Derive token usage \((\text{input}, \text{output}, \text{total})\) from the provider-specific usage fields.
    \item Convert token usage into a dollar cost using the per-million-token prices in \texttt{config/models.yaml}.
    \item Write a Langfuse trace/span with:
    \begin{itemize}
        \item metadata: \texttt{model}, \texttt{provider}, \texttt{custom\_id}, optional \texttt{run\_id};
        \item the parsed input and raw provider response;
        \item three scores:
        \begin{itemize}
            \item \texttt{accuracy} \(\in \{0,1\}\) (per-trace correctness),
            \item \texttt{error\_type} \(\in\)\{\texttt{true\_positive}, \texttt{false\_negative}, \texttt{true\_negative}, \texttt{false\_positive}\},
            \item \texttt{cost\_usd} (total dollar cost for this trace);
        \end{itemize}
        \item detailed \texttt{usage\_details} and \texttt{cost\_details} for debugging and audits.
    \end{itemize}
\end{enumerate}

On top of this logging layer, a small Streamlit dashboard queries Langfuse and aggregates scores over the 300-example monitoring subset.
The public instance of this dashboard is available at \url{https://llm-eval-dashboard.streamlit.app/}, and the underlying evaluation code is open-sourced at \url{https://github.com/gocomo/llm-batch-eval}.
The dashboard provides:
\begin{itemize}
    \item per-model accuracy curves over time (mean of the per-trace \texttt{accuracy} scores),
    \item confusion-matrix summaries derived from \texttt{error\_type},
    \item request volume and latency distributions per run,
        \item and cost views such as cost per run and estimated cost per 1,000 inferences.
\end{itemize}
Screenshots from this Streamlit dashboard are used in the experiments chapter to show concrete drift events and the associated accuracy--cost trade-offs.
Together, \texttt{ingest.py} and the dashboard form the practical monitoring surface of the statistical surveillance loop described in the previous chapters.
\chapter{Conclusion}
This thesis provides a statistically grounded, cost-aware framework for the continuous evaluation of LLMs in production. By decoupling the initial reference benchmark from an informative monitoring subset, and pairing statistical drift detection with automated prompt optimization, organizations can maintain high classification performance despite the inherent instability of black-box LLM APIs.
