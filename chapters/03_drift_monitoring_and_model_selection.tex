\chapter{Drift Monitoring and Model Selection Methodology}
\label{ch:drift}

Chapter~\ref{ch:data} fixes the monitoring panel $\mathcal{D}_n=\{(x_i,y_i)\}_{i=1}^{n}$ with $n=300$. This chapter specifies repeated evaluation on $\mathcal{D}_n$, paired drift detection via McNemar's test, classification metrics for reporting and candidate comparison, a cost-based expected-cost utility as one formalisation of deployment choice, and manual operator overrides. The estimand is \emph{change in deployment behaviour on $\mathcal{D}_n$}; it does not identify the population risk $R_t(f)$ from Chapter~\ref{ch:data} without additional assumptions.

\section{Temporal evaluation on a fixed panel}
\label{sec:formalisation-temporal}

Let $t\in\{1,\ldots,T\}$ index discrete evaluation batches (e.g.\ weekly). At each $t$, each model under study is evaluated on the \emph{same} $\mathcal{D}_n$. Cross-time differences are attributable to changes in predictions or parsing, not to resampling of items.

For instance $i$ and time $t$, let $\hat{y}_{i,t}\in\{0,1\}$ be the predicted label and
\begin{equation}
    E_{i,t} = \mathbb{I}(\hat{y}_{i,t}=y_i)
\end{equation}
the correctness indicator. Unless noted otherwise, $\hat{y}_{i,t}$ and $E_{i,t}$ refer to the current deployment $m_{\mathrm{curr}}$ in Sections~\ref{sec:formalisation-temporal}--\ref{sec:mcnemar-section}. Section~\ref{sec:model-comparison-manual} compares candidates $m\in\mathcal{M}_{\mathrm{cand}}$ and writes $\hat{A}_t(m)$ explicitly.

For any $m\in\mathcal{M}_{\mathrm{cand}}$, let $\hat{y}_{i,t}(m)$ denote $m$'s prediction on instance $i$ at time $t$. Define empirical accuracy on $\mathcal{D}_n$ by
\begin{equation}
    \hat{A}_t(m) = \frac{1}{n}\sum_{i=1}^{n} \mathbb{I}\bigl(\hat{y}_{i,t}(m)=y_i\bigr).
\end{equation}
For $m=m_{\mathrm{curr}}$, write $\hat{A}_t:=\hat{A}_t(m_{\mathrm{curr}})=\frac{1}{n}\sum_{i=1}^n E_{i,t}$. The sequence $(\hat{A}_t)_{t=1}^T$ is \emph{not} a sequence of independent Bernoulli means: the same units are reused. Marginal comparisons of $\hat{A}_{t_1}$ and $\hat{A}_{t_2}$ that assume independence (e.g.\ two-proportion $z$-tests) overstate precision. Drift detection uses paired structure via $(E_{i,t_1},E_{i,t_2})$ (Section~\ref{sec:mcnemar-section}).

\section{Statistical drift detection via McNemar's test}
\label{sec:mcnemar-section}

Drift analysis targets \emph{per-instance} changes in correctness between times $t_1$ and $t_2$, not the marginal difference $\hat{A}_{t_2}-\hat{A}_{t_1}$ alone.

\subsection{Contingency table}

Compare $(E_{i,t_1},E_{i,t_2})$ for each $i\in\{1,\ldots,n\}$. The four outcomes partition $\mathcal{D}_n$:

\begin{table}[htbp]
    \centering
    \caption{Paired $2\times2$ table for correctness at $t_1$ and $t_2$.}
    \label{tab:mcnemar_contingency}
    \begin{tabular}{c|p{0.35\textwidth}p{0.35\textwidth}}
        & \centering $E_{i,t_2}=1$ & \centering $E_{i,t_2}=0$ \tabularnewline
        \hline
        $E_{i,t_1}=1$
            & \centering $\displaystyle a = \sum_{i=1}^{n} \mathbb{I}(E_{i,t_1}=1,\; E_{i,t_2}=1)$
            & \centering $\displaystyle b = \sum_{i=1}^{n} \mathbb{I}(E_{i,t_1}=1,\; E_{i,t_2}=0)$ \tabularnewline
        $E_{i,t_1}=0$
            & \centering $\displaystyle c = \sum_{i=1}^{n} \mathbb{I}(E_{i,t_1}=0,\; E_{i,t_2}=1)$
            & \centering $\displaystyle d = \sum_{i=1}^{n} \mathbb{I}(E_{i,t_1}=0,\; E_{i,t_2}=0)$ \tabularnewline
    \end{tabular}
\end{table}

Then $a+b+c+d=n$. Concordant cells $a$ and $d$ carry no information on directional change; evidence is in $b$ (regressions) and $c$ (improvements). Moreover
\begin{equation}
    \hat{A}_{t_1} = \frac{a+b}{n},
    \qquad
    \hat{A}_{t_2} = \frac{a+c}{n},
    \qquad
    \hat{A}_{t_2}-\hat{A}_{t_1} = \frac{c-b}{n}.
\end{equation}

\subsection{Test statistic and alerting rule}

Let $p_b$ and $p_c$ denote population counterparts of $b/n$ and $c/n$ under the monitoring process on $\mathcal{D}_n$. McNemar tests $H_0:p_b=p_c$ against the one-sided alternative $H_a:p_b>p_c$ when degradation is the operational concern. With continuity correction,
\begin{equation}
    \chi^2 = \frac{(|b-c|-1)^2}{b+c},
\end{equation}
approximately $\chi^2_1$ for large $m=b+c$ (when $b+c>0$).

A \textbf{statistical drift alert} is registered when (i) $b>c$ and (ii) the one-sided $p$-value is below $\alpha=0.05$. Condition (i) excludes net improvements. If $b+c=0$, the test is degenerate and no directional conclusion is drawn.

\subsection{Empirical examples from monitoring runs}

Tables~\ref{tab:mcnemar_gpt5_meth} and~\ref{tab:mcnemar_gpt5mini_meth} show paired contingency tables from two batch comparisons on the $n=300$ monitoring subset (8~March~2026 vs.\ 10~March~2026).

    \centering
    \caption{McNemar table for \texttt{gpt-5} between 8~March~2026 and 10~March~2026 on $\mathcal{D}_n$.}
    \label{tab:mcnemar_gpt5_meth}
    \begin{tabular}{c|cc}
        & 2026-03-10 correct & 2026-03-10 wrong \\
        \hline
        2026-03-08 correct & 291 & 0 \\
        2026-03-08 wrong   & 0   & 9 \\
    \end{tabular}

Here $(b,c)=(0,0)$: no discordant pairs, so McNemar's statistic is undefined and no temporal change in correctness is detectable on the panel.

\section{Classification metrics on the monitoring subset}
\label{sec:classification-metrics}

All metrics below are computed on $\mathcal{D}_n$ (Section~\ref{sec:informative-sampling-disagreement}). They describe behaviour on the \emph{disagreement-enriched} panel: ranks and levels need not match full-benchmark $A_N(t)$ (Section~\ref{sec:selection-bias}).

Let $\mathrm{TP}_t$, $\mathrm{FP}_t$, $\mathrm{TN}_t$, and $\mathrm{FN}_t$ be confusion counts on $\mathcal{D}_n$ at time $t$ for a given model and a fixed rule mapping provider output to $\hat{y}_{i,t}\in\{0,1\}$. Omit each ratio when its denominator is zero.

\paragraph{Accuracy.}
Empirical accuracy is
\begin{equation}
    \widehat{\mathrm{Acc}}_t = \frac{\mathrm{TP}_t+\mathrm{TN}_t}{\mathrm{TP}_t+\mathrm{TN}_t+\mathrm{FP}_t+\mathrm{FN}_t},
\end{equation}
equal to $\hat{A}_t$ for the same model and threshold. It summarises global correctness but weights errors by class prevalence on $\mathcal{D}_n$.

\paragraph{Precision, recall, and F1.}
\begin{equation}
    \widehat{\mathrm{Prec}}_t = \frac{\mathrm{TP}_t}{\mathrm{TP}_t+\mathrm{FP}_t},
    \qquad
    \widehat{\mathrm{Rec}}_t = \frac{\mathrm{TP}_t}{\mathrm{TP}_t+\mathrm{FN}_t},
    \qquad
    \widehat{\mathrm{F}}_{1,t} = \frac{2\,\widehat{\mathrm{Prec}}_t\,\widehat{\mathrm{Rec}}_t}{\widehat{\mathrm{Prec}}_t+\widehat{\mathrm{Rec}}_t}.
\end{equation}
Precision is positive predictive value; recall is sensitivity on the positive class. The $F_1$ score is their harmonic mean when both are defined and $\widehat{\mathrm{Prec}}_t+\widehat{\mathrm{Rec}}_t>0$.

\paragraph{Specificity and balanced accuracy.}
\begin{equation}
    \widehat{\mathrm{Spec}}_t = \frac{\mathrm{TN}_t}{\mathrm{TN}_t+\mathrm{FP}_t},
    \qquad
    \widehat{\mathrm{BA}}_t = \tfrac{1}{2}\bigl(\widehat{\mathrm{Rec}}_t + \widehat{\mathrm{Spec}}_t\bigr).
\end{equation}
Balanced accuracy mitigates inflation of raw accuracy under prevalence skew on the panel.

\paragraph{Ranking summaries.}
When the pipeline exposes scored outputs (not only hard labels), a precision--recall curve traces $(\widehat{\mathrm{Rec}},\widehat{\mathrm{Prec}})$ over thresholds; its area (PR--AUC) summarises ranking quality in $[0,1]$ and can be more informative than ROC--AUC under imbalance. Drift \emph{alerts} remain based on McNemar on hard correctness (Section~\ref{sec:mcnemar-section}), not on PR--AUC.

\section{Model comparison and deployment choice}
\label{sec:model-comparison-manual}

Candidate models $m\in\mathcal{M}_{\mathrm{cand}}$ are compared using $\hat{A}_t(m)$, $\widehat{\mathrm{Prec}}_t(m)$, $\widehat{\mathrm{Rec}}_t(m)$, $\widehat{\mathrm{F}}_{1,t}(m)$, and average inference cost $C_t(m)$ (USD per request from logged usage and pricing), all on $\mathcal{D}_n$. Campaigns differ in the relative cost of false positives and false negatives.

While the thesis presents a cost-based utility in Section~\ref{sec:deployment-utility} as one formalisation of the accuracy--cost trade-off, final deployment decisions incorporate \emph{manual} judgment alongside these metrics (tolerance to error types, budget, latency, provider policy).

Two decision layers are kept separate: (i) paired significance of degradation for $m_{\mathrm{curr}}$ via Section~\ref{sec:mcnemar-section}; (ii) multi-criteria comparison of candidates using the metrics above and $C_t(m)$, optionally summarised by the expected cost $E_t[\mathcal{C}](m)$ below. If no acceptable fallback exists, prompt optimisation may be attempted before changing the API model (Chapter~\ref{chap:prompt-optimisation}). Exported numeric panels and dashboards used in experiments are described in Chapter~\ref{chap:system-architecture}.

\section{Cost-aware deployment utility}
\label{sec:deployment-utility}

This section derives a per-request expected cost that combines inference expenditure with asymmetric misclassification penalties, giving operators a single scalar for model ranking.

\subsection{Cost components}

Every request to model $m$ at evaluation time $t$ incurs two costs:
\begin{enumerate}
    \item \textbf{Inference cost} $C_t(m)$: the API charge in USD per request, observed from logged usage and pricing (same units as in Section~\ref{sec:model-comparison-manual}).
    \item \textbf{Business error cost}: a penalty that depends on the prediction outcome. Correct predictions (TP, TN) incur no additional cost. Misclassifications carry:
    \begin{itemize}
        \item $C_{\mathrm{FP}}$: cost of a false positive (e.g.\ an irrelevant post flagged as relevant triggers unnecessary downstream processing),
        \item $C_{\mathrm{FN}}$: cost of a false negative (e.g.\ a relevant post is missed, causing a gap in campaign coverage).
    \end{itemize}
\end{enumerate}

\subsection{Derivation of per-request expected cost}

\paragraph{Step 1: confusion-matrix decomposition.}
On an evaluation batch $\mathcal{D}_n$ of $n$ labelled items, model $m$ at time $t$ produces confusion counts $\mathrm{TP}_t(m)$, $\mathrm{FP}_t(m)$, $\mathrm{TN}_t(m)$, $\mathrm{FN}_t(m)$ with $\mathrm{TP}_t+\mathrm{FP}_t+\mathrm{TN}_t+\mathrm{FN}_t=n$.

\paragraph{Step 2: total batch cost.}
Summing inference and error costs over the batch:
\begin{equation}
    \mathrm{TotalCost}_t(m)
    = \underbrace{n \cdot C_t(m)}_{\text{inference}}
    + \underbrace{C_{\mathrm{FP}}\cdot\mathrm{FP}_t(m)
    + C_{\mathrm{FN}}\cdot\mathrm{FN}_t(m)}_{\text{business error cost}}.
\end{equation}

\paragraph{Step 3: per-request expected cost.}
Dividing by $n$ yields the expected cost per request:
\begin{equation}
\label{eq:expected-cost}
    E_t[\mathcal{C}](m)
    = C_t(m)
    + \frac{C_{\mathrm{FP}}\cdot\mathrm{FP}_t(m)
          + C_{\mathrm{FN}}\cdot\mathrm{FN}_t(m)}{n}.
\end{equation}

\paragraph{Step 4: model selection rule.}
The preferred deployment model minimises expected cost:
\begin{equation}
\label{eq:model-selection}
    m_t^\star
    \;\in\;
    \arg\min_{m\in\mathcal{M}_{\mathrm{cand}}}\;
    E_t[\mathcal{C}](m).
\end{equation}

\subsection{Rate form}

Let $\hat{\pi}_t=(\mathrm{TP}_t+\mathrm{FN}_t)/n$ denote the empirical positive prevalence on $\mathcal{D}_n$. Then
\[
    \frac{\mathrm{FP}_t(m)}{n}
    = \widehat{\mathrm{FPR}}_t(m)\,(1-\hat{\pi}_t),
    \qquad
    \frac{\mathrm{FN}_t(m)}{n}
    = \widehat{\mathrm{FNR}}_t(m)\,\hat{\pi}_t,
\]
so~\eqref{eq:expected-cost} is equivalently
\begin{equation}
\label{eq:expected-cost-rate}
    E_t[\mathcal{C}](m)
    = C_t(m)
    + C_{\mathrm{FP}}\,\widehat{\mathrm{FPR}}_t(m)\,(1-\hat{\pi}_t)
    + C_{\mathrm{FN}}\,\widehat{\mathrm{FNR}}_t(m)\,\hat{\pi}_t.
\end{equation}
This form makes explicit that the FN penalty is weighted by prevalence $\hat{\pi}_t$ and the FP penalty by $1-\hat{\pi}_t$.

\subsection{Operator parameters}

Two business parameters must be supplied:
\begin{itemize}
    \item $C_{\mathrm{FP}}$: monetary cost of one false positive,
    \item $C_{\mathrm{FN}}$: monetary cost of one false negative.
\end{itemize}
For \emph{ranking} models only their ratio $r=C_{\mathrm{FN}}/C_{\mathrm{FP}}$ matters, because the absolute scale of $C_{\mathrm{FP}}$ cancels in $\arg\min$. $r$ answers the question: ``how many false-positive reviews is one missed relevant post worth?''

\paragraph{Remark on prevalence and the monitoring panel.}
On the full benchmark ($n=1199$; $682$ positive, $517$ negative) the prevalence is $\hat{\pi}\approx0.569$. On the monitoring panel ($n=300$; $250$ positive, $50$ negative) it is $\hat{\pi}\approx0.833$. Because the panel is $83\%$ positive, FN errors are roughly five times more likely than FP errors by base rate alone. A model with high $\widehat{\mathrm{FNR}}$ is therefore heavily penalised on the monitoring set even before applying $C_{\mathrm{FN}}$. The dataset used to evaluate $E_t[\mathcal{C}]$ should match the production class distribution.

\subsection{Monitor--detect--act pipeline}

After each batch evaluation the following logic applies:
\begin{enumerate}
    \item \textbf{Monitor:} compute McNemar statistics for $m_{\mathrm{curr}}$ on $\mathcal{D}_n$ relative to a chosen baseline time.
    \item \textbf{Detect:} register a drift event if $b>c$ and the one-sided $p$-value is below $\alpha$ (Section~\ref{sec:mcnemar-section}).
    \item \textbf{Act:} compare candidates via $E_t[\mathcal{C}](m)$; operators set $C_{\mathrm{FP}}$ and $C_{\mathrm{FN}}$ (or equivalently $r$) to reflect campaign priorities. If no acceptable fallback exists, trigger prompt optimisation (Chapter~\ref{chap:prompt-optimisation}) before switching the API model identifier.
\end{enumerate}

The selected deployment model is $m_t^\star$ from~\eqref{eq:model-selection}; when operators prefer not to commit to a single scalar rule, they choose $m_{\mathrm{curr}}$ from the same metrics without computing $E_t[\mathcal{C}]$.
