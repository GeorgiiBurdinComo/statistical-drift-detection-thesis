\chapter{Prompt Optimisation as an Adaptive Mechanism}
\label{chap:prompt-optimisation}

\section{Motivation and problem statement}
\label{sec:motivation-prompt-adaptation}

After a McNemar alert (Section~\ref{sec:mcnemar-section}), the only controllable part of the API classifier is the prompt \(\pi\): weights \(\theta_t\) are provider-side. Manual rewriting does not scale, so automatic prompt optimisation (APO) is the adaptive step after statistically established degradation.

Let
\begin{equation}
    f_t(x;\pi)=f(x;\pi,\theta_t).
\end{equation}
APO searches for a revised hard prompt \(\pi^\star\) that restores predictive quality for the same API model under a limited rollout budget.

\section{Automatic prompt optimisation}
\label{sec:general-formulation-apo}

APO is discrete black-box search: seed prompts, generate candidates, evaluate on labelled examples, retain promising ones, stop on budget. With optimisation set \(\mathcal{D}_{\mathrm{opt}}=\{(x_i,y_i)\}_{i=1}^{n_{\mathrm{opt}}}\) and admissible prompts \(\mathcal{P}\subseteq\Sigma^\star\),
\begin{equation}
    J_t(\pi)
    =
    \frac{1}{n_{\mathrm{opt}}}
    \sum_{i=1}^{n_{\mathrm{opt}}}
    \mathbb{I}\!\left(f_t(x_i;\pi)=y_i\right),
    \qquad
    \pi_t^\star \in \arg\max_{\pi\in\mathcal{P}} J_t(\pi)
    \quad\text{s.t.}\quad
    N_{\mathrm{roll}}\le B.
\end{equation}
Minibatch evaluations replace exact \(J_t\) in practice, so search is noisy as well as discrete.

Three constraints fix the leaf: black-box API access, expensive rollouts, and disagreement-heavy optimisation data (Section~\ref{sec:selection-bias}) where average score can hide new regressions. Soft-prompt and gradient methods are unavailable. The relevant leaf is therefore black-box discrete search with score and/or textual feedback, reflective or evolutionary edits, and retention that does not collapse immediately to one greedy incumbent.

GEPA (Genetic--Pareto Evolutionary Prompt Optimisation)~\cite{agrawal2025gepa} sits on that leaf: seed prompt, task scores plus textual feedback, reflective mutation, Pareto population retention. Reported sample efficiency against GRPO and MIPROv2~\cite{opsahlong2024mipro,agrawal2025gepa} makes it a reasonable choice under limited budget; it also returns ordinary hard prompts that stay inspectable and deployable.

\section{GEPA}
\label{sec:gepa}

In the original paper, GEPA targets compound systems with several prompt modules. Here the classifier has one module, so a candidate is identified with its prompt \(\pi\).

\subsection{Core idea}

GEPA combines reflective mutation (new prompts from traces, scores, and textual feedback), population search (a pool of accepted prompts), and Pareto-based parent selection (prefer candidates that are best on different examples, not only the average-best).

\subsection{Algorithmic workflow}

GEPA splits the optimisation data into two disjoint parts,
\begin{equation}
    \mathcal{D}_{\mathrm{opt}}
    =
    D_{\mathrm{feedback}}\cup D_{\mathrm{pareto}},
    \qquad
    D_{\mathrm{feedback}}\cap D_{\mathrm{pareto}}=\varnothing.
\end{equation}
The feedback set generates local improvement signals; the Pareto set is used for candidate comparison and parent selection.

At iteration \(k\), GEPA proceeds as follows:
\begin{enumerate}
    \item select a parent prompt from a Pareto-filtered subset of the current pool;
    \item run the parent on a minibatch
    \begin{equation}
        M_k \subseteq D_{\mathrm{feedback}};
    \end{equation}
    \item collect outputs, traces, scores, and evaluator feedback;
    \item use a reflection model to propose an offspring prompt \(\widetilde{\pi}_k\);
    \item accept the offspring if it improves the minibatch score
    \begin{equation}
        \widehat{J}_{t,k}(\widetilde{\pi}_k)>\widehat{J}_{t,k}(\pi_k);
    \end{equation}
    \item if accepted, add it to the pool and evaluate it on \(D_{\mathrm{pareto}}\).
\end{enumerate}

The search stops when the rollout budget is exhausted. The final returned prompt is the candidate with the strongest aggregate score on \(D_{\mathrm{pareto}}\).

\subsection{Why Pareto selection matters}

Greedy search from the average-best prompt can stall. On disagreement-heavy data a prompt can fix some hard items and break others; keeping non-dominated prompts that win on different instances preserves that trade-off until selection time.

\subsection{Compact formalisation}

Let
\begin{equation}
    D_{\mathrm{pareto}}=\{(x_1,y_1),\dots,(x_{n_p},y_{n_p})\}
\end{equation}
be the validation subset used for Pareto-based selection. For a prompt \(\pi\), define
\begin{equation}
    v_i(\pi)=\mathbb{I}\!\left(f_t(x_i;\pi)=y_i\right),
    \qquad i=1,\dots,n_p,
\end{equation}
and \(\mathbf{v}(\pi)=\bigl(v_1(\pi),\dots,v_{n_p}(\pi)\bigr)\). Optimisation is multi-objective in the Pareto sense: \(\max_{\pi\in\mathcal{P}} \mathbf{v}(\pi)\).

\begin{definition}[Pareto dominance]
For prompts \(\pi^{(A)}\) and \(\pi^{(B)}\), write \(\pi^{(A)} \succ \pi^{(B)}\) if
\(v_i(\pi^{(A)}) \ge v_i(\pi^{(B)})\) for all \(i\) and \(v_j(\pi^{(A)}) > v_j(\pi^{(B)})\) for at least one \(j\).
\end{definition}

Let \(\mathcal{C}_k\) be the accepted prompt pool after iteration \(k\). For each validation instance \(i\),
\begin{equation}
    \mathcal{P}_{k,i}^\star
    =
    \arg\max_{\pi\in\mathcal{C}_k} v_i(\pi),
    \qquad
    \mathcal{U}_k
    =
    \bigcup_{i=1}^{n_p} \mathcal{P}_{k,i}^\star.
\end{equation}
GEPA removes dominated prompts and keeps
\begin{equation}
    \widehat{\mathcal{F}}_k
    =
    \left\{
        \pi\in\mathcal{U}_k
        \;\middle|\;
        \nexists \tilde{\pi}\in\mathcal{U}_k \text{ such that } \tilde{\pi}\succ \pi
    \right\}.
\end{equation}
A parent is sampled from \(\widehat{\mathcal{F}}_k\), with higher weight for prompts that are best on more instances.

\subsection{Regression and recovery relative to the deployed prompt}

Let \(\pi_0\) be the deployed prompt and \(\pi\) a candidate. With \(s_i(\pi)=\mathbb{I}\!\left(f_t(x_i;\pi)=y_i\right)\),
\begin{align}
    R_{\mathrm{new}}(\pi\mid\pi_0)
    &=
    \sum_{i=1}^{n_{\mathrm{opt}}}
    \mathbb{I}\bigl(s_i(\pi_0)=1,\;s_i(\pi)=0\bigr),
    \\
    G_{\mathrm{fix}}(\pi\mid\pi_0)
    &=
    \sum_{i=1}^{n_{\mathrm{opt}}}
    \mathbb{I}\bigl(s_i(\pi_0)=0,\;s_i(\pi)=1\bigr),
\end{align}
so
\begin{equation}
    J_t(\pi)-J_t(\pi_0)
    =
    \frac{G_{\mathrm{fix}}(\pi\mid\pi_0)-R_{\mathrm{new}}(\pi\mid\pi_0)}
    {n_{\mathrm{opt}}}.
\end{equation}
A scalar objective sees only the net; GEPA can keep candidates with different \((R_{\mathrm{new}},G_{\mathrm{fix}})\) profiles, which matters when avoiding new regressions is almost as important as fixing old errors.

In the monitoring loop (Figure~\ref{fig:run-decision-logic}), APO is the adapt branch after a confirmed alert: repair on \(\mathcal{D}_{\mathrm{opt}}\), then re-evaluate on \(\mathcal{D}_n\) and compare on \(\mathcal{D}_N\) like any other deployment candidate.
