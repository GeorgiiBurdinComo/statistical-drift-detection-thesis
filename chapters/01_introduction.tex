\chapter{Introduction}

\section{Context and motivation}
This thesis studies a small applied-mathematics problem with a direct operational consequence: how to make decisions from repeated, costly observations of a black-box classifier whose behaviour is not assumed to be stationary. The application is campaign-relevance detection at GOCOMO GmbH, where batches of social-media posts are classified as relevant or not relevant to a campaign. Manual review does not scale to the incoming volume, while an erroneous automatic decision creates a campaign-dependent cost.

At time \(t\), an API configuration is therefore treated as a function \(q_t\) observed only through its inputs and outputs. Repeating a fixed benchmark reveals changes in those outputs. Provider-side model state, nondeterminism, request handling, and the surrounding evaluation pipeline are observationally equivalent possible sources of such changes. Behavioural variation of API models has also been documented in prior work~\cite{chen2023chatgpt,echterhoff2024muscle}.

The resulting design problem has two constraints. First, evaluating every model repeatedly on the full labelled benchmark is expensive. Second, a statistically significant change is not yet a deployment decision: the importance of false positives and false negatives, together with inference price, determines which candidate is useful. The methodology must consequently connect statistical detection to decision cost without confusing their roles.

\section{Problem statement and analytical decomposition}
Let \(x_i\) denote multimodal post \(i\), \(y_i\in\{0,1\}\) its reference label, and \(\hat y_{i,t}(q)=q_t(x_i)\) the API output from configuration \(q\). The objective is to obtain reproducible evidence about changes in the observable mapping and to turn that evidence into an operational action.

Three functions are kept separate throughout:
\begin{enumerate}
    \item \textbf{Inference} fixes the task, prompt, request schema, parsing rule, and labelled benchmark used to obtain \(\hat y_{i,t}(q)\).
    \item \textbf{Monitoring} compares paired correctness outcomes over time on a fixed, economical panel and raises an alert; it does not select a replacement model.
    \item \textbf{Ranking} evaluates deployment candidates on the full benchmark under predictive error costs and inference cost; it does not reuse the deliberately non-representative monitoring panel as a leaderboard.
\end{enumerate}
This separation is central: detection and selection answer different mathematical questions and require different data.

\section{Scope and contributions}
The scope is binary, multimodal campaign-relevance classification through black-box batch APIs. The empirical evidence comprises one existing labelled benchmark, a fixed monitoring panel, and repeated observations over a finite monitoring window.

Within that scope, the thesis contributes:
\begin{itemize}
    \item a formal evaluation target for a time-indexed black-box classifier and a disagreement-based monitoring panel with an explicit power calculation;
    \item a paired alerting rule based on exact McNemar tests, multiplicity control, and an operational effect-size condition;
    \item a cost-aware ranking rule that combines false-positive, false-negative, and inference costs on the full benchmark; and
    \item a reproducible weekly implementation with explicit run identity and replayable artifacts.
\end{itemize}

\section{Research questions}
\label{sec:research-questions}
The four questions follow the operational sequence and permit negative or qualified answers:
\begin{enumerate}
    \item[RQ1:] How can campaign relevance be represented as binary classification by a time-indexed black-box API while keeping the empirical evaluation target distinct from population risk?
    \item[RQ2:] How much cost can a reduced monitoring panel save, and for which levels of output discordance does it retain useful power to detect degradation?
    \item[RQ3:] Which paired statistical and operational conditions should trigger an alert, and how should repeated comparisons be controlled?
    \item[RQ4:] How should deployment candidates be ranked when false positives, false negatives, and inference calls have different costs?
\end{enumerate}

\section{Task definition}
For each post, the request combines a campaign definition with textual context---caption, transcription, hashtags, mentions, and metadata---and selected images or video frames. The current strict response schema requires the boolean field \texttt{campaign\_relevant} and an auxiliary string \texttt{relevancy\_reasoning}; only the boolean is scored. \section{Structure of the thesis}
\label{sec:thesis-structure}
Chapter~\ref{ch:data} defines the benchmark, sentinel panel, and evaluation quantities. Chapter~\ref{ch:drift} develops paired monitoring, and Chapter~\ref{ch:cost-deployment-utility} separates an alert from the later deployment decision. Chapter~\ref{chap:system-architecture} maps these components to a reproducible implementation, and Chapter~\ref{chap:experimental-results} reports the monitoring and cost evidence. The conclusion answers the research questions and states the limits of the available evidence.
