\chapter{Evaluation Design and Monitoring Panel}
\label{ch:data}

\noindent This chapter defines the fixed 1199-item benchmark and the 300-item monitoring panel. The panel is a disagreement-enriched sensitivity set that makes repeated paired checks cheaper and more sensitive to behavioural change. Panel design therefore has two parts: size and item selection.

\section{Formal problem definition}

The formal setup uses the following basic objects:
\begin{description}
    \item[\(x\)] one multimodal social-media post;
    \item[\(y\)] reference label, where \(y\in\{0,1\}\), \(1\) means campaign-relevant, and \(0\) means not campaign-relevant;
    \item[\(t\)] evaluation time;
    \item[\(q_t\)] binary classifier induced by one complete API configuration at time \(t\).
\end{description}
\begin{equation}
    q_t(x)\in\{0,1\}.
    \label{eq:time-indexed-classifier}
\end{equation}

It is useful to separate two parts of this configuration:
\begin{description}
    \item[\(c_t\)] client-controlled request contract: provider endpoint, prompt text, request schema, parser, and any exposed inference settings available for that model;
    \item[\(h_t\)] hidden provider-side state: inaccessible weights, routing, safety layers, and any remaining server-side randomness.
\end{description}
Controls such as temperature and seed are client-side mechanisms for reducing sampling variation and, where supported, for making repeated requests more reproducible. OpenAI documents that Chat Completions parameter support differs by model, particularly for reasoning models, and that the optional seed parameter is only a Beta, best-effort control~\cite{openai2026chatcompletions}. Uniform request-level determinism therefore cannot be imposed across the monitored model set, and remaining sampling variability stays inside \(h_t\).

For labelled item \((x_i,y_i)\), the returned prediction is written as
\begin{equation}
    \hat y_{i,t}(q)=Q(x_i;c_t,h_t)=q_t(x_i).
    \label{eq:item-prediction}
\end{equation}

In the passive monitoring setting, comparisons keep the client-controlled contract fixed and observe how the resulting black-box mapping behaves over time.

\section{Reference benchmark, operational constraint, and monitoring subset}
\label{sec:input-datasets}

Evaluation uses a fixed labelled benchmark
\begin{equation}
    \mathcal{D}_N
    =
    \{(x_i,y_i)\}_{i=1}^{N},
    \qquad
    N=1199.
    \label{eq:full-benchmark}
\end{equation}
For API configuration \(q\) evaluated at time \(t\), benchmark accuracy is
\begin{equation}
    A_N(q,t)
    =
    \frac{1}{N}
    \sum_{i=1}^{N}
    \mathbb{I}\{\hat y_{i,t}(q)=y_i\}.
    \label{eq:finite-benchmark-accuracy}
\end{equation}
This is the proportion of the 1199 benchmark posts classified correctly. Since the benchmark was not obtained through a documented probability sample from production, \(A_N(q,t)\) describes performance on this fixed dataset rather than an unbiased estimate of production accuracy.

The benchmark labels were assigned manually by human annotators. Where initial judgements differed, the final reference label was resolved by discussion and then frozen for all subsequent evaluations.
The public code repository \url{https://github.com/GeorgiiBurdinComo/llm-batch-eval} stores the frozen reproducibility inputs for this benchmark and for the derived monitoring panel.

Repeatedly evaluating every monitored configuration on all \(N=1199\) items is expensive. Monitoring therefore relies on a smaller fixed subset
\begin{equation}
    \mathcal{D}_n
    =
    \{(x_i,y_i):i\in\mathcal{I}_n\}
    \subset\mathcal{D}_N,
    \qquad
    |\mathcal{I}_n|=n.
    \label{eq:sentinel-panel}
\end{equation}
Once selected, the identifiers in \(\mathcal{I}_n\) and their labels are frozen and reused at every monitoring time. This keeps the comparison paired: the item seen today is the same item seen at baseline.

The corresponding panel accuracy is
\begin{equation}
    A_n(q,t)
    =
    \frac{1}{n}
    \sum_{i\in\mathcal{I}_n}
    \mathbb{I}\{\hat y_{i,t}(q)=y_i\}.
    \label{eq:finite-panel-accuracy}
\end{equation}
This is the primary monitoring estimand. It measures performance on the frozen panel and is used for repeated monitoring.

Panel design requires two decisions:
\begin{enumerate}
    \item how large \(n\) must be for repeated paired checks to remain informative;
    \item by which rule the identifiers in \(\mathcal{I}_n\) should be chosen so that the panel is sensitive to behavioural change.
\end{enumerate}
The next two sections address these decisions for the implemented monitoring design.

\section{Monitoring subset size}
\label{sec:monitoring-sample-size}

Size planning refers to one paired comparison of the same panel between two evaluation times, say \(t_1\) and \(t_2\). For item \(i\), write
\[
E_{i,t}=\mathbb{I}\{\hat y_{i,t}(q)=y_i\}\in\{0,1\}
\]
for correctness at time \(t\). The pair \((E_{i,t_1},E_{i,t_2})\) then falls into the standard \(2\times2\) paired-correctness table:

\begin{table}[H]
    \centering
    \caption[Paired correctness table for size planning]{The four possible correctness transitions for one fixed-panel comparison.}
    \label{tab:mcnemar_contingency_design}
    \begin{tabular}{c|cc}
        & Follow-up correct: \(E_{i,t_2}=1\)
        & Follow-up wrong: \(E_{i,t_2}=0\) \\
        \hline
        Baseline correct: \(E_{i,t_1}=1\)
        & \(a\): stayed correct
        & \(b\): regressed \((1\to0)\) \\
        Baseline wrong: \(E_{i,t_1}=0\)
        & \(c\): improved \((0\to1)\)
        & \(d\): stayed wrong
    \end{tabular}
\end{table}

The four cells partition the paired comparison, so \(a+b+c+d=n\). Their probabilities are denoted \(p_a,p_b,p_c,p_d\), with \(p_a+p_b+p_c+p_d=1\). McNemar's test uses the discordant outcomes \(b\) and \(c\): \(b\) counts correct-to-wrong transitions, and \(c\) counts wrong-to-correct transitions.

\begin{assumption}[Working model for design sensitivity]
For a candidate panel size \(n\), the \(n\) paired correctness outcomes are treated as independent draws from this common four-outcome distribution. An item regresses with probability \(p_b\) and improves with probability \(p_c\).
\label{ass:chapter2-power-model}
\end{assumption}

Assumption~\ref{ass:chapter2-power-model} is a design model for planned sensitivity of the paired test.

It is convenient to separate the probability of any correctness change from its net degradation:
\begin{equation}
    \rho=p_b+p_c,
    \qquad
    g=p_b-p_c.
    \label{eq:rho-g-definition}
\end{equation}
Here \(\rho\) is the discordance probability and \(g\) is the expected loss in accuracy on the fixed design. Equivalently,
\begin{align}
    p_b&=\frac{\rho+g}{2},\\
    p_c&=\frac{\rho-g}{2}.
    \label{eq:rho-g-inverse}
\end{align}
Admissible degradation scenarios satisfy
\begin{equation}
    0\le g\le\rho\le1.
    \label{eq:admissible-power-region}
\end{equation}

Under the working model, each paired item is discordant with probability \(\rho=p_b+p_c\). The total number of discordant pairs on a panel of size \(n\) therefore follows a binomial law:

If \(D\) is the number of discordant pairs on a panel of size \(n\), then
\begin{equation}
    D\sim\mathrm{Binomial}(n,\rho).
    \label{eq:discordance-binomial}
\end{equation}
Let \(B\) denote the number of regressions among these \(D\) discordant pairs.
Conditional on discordance, the probability that the changed item is specifically a regression is
\begin{equation}
P(\text{regression}\mid\text{discordant})
=
\frac{p_b}{p_b+p_c}
=
\frac{p_b}{\rho}
=
\frac{\rho+g}{2\rho}.
\label{eq:design-conditional-regression-probability}
\end{equation}
Therefore, once \(d\) discordant items have been observed, the number of regressions among them is binomial with \(d\) trials and conditional regression probability \((\rho+g)/(2\rho)\):

Conditional on \(D=d\), the number of regressions among discordant items satisfies
\begin{equation}
    B\mid D=d
    \sim
    \mathrm{Binomial}
    \left(
        d,\frac{\rho+g}{2\rho}
    \right).
    \label{eq:conditional-binomial}
\end{equation}
Under the boundary null of no directional degradation, regressions and improvements are equally likely among discordant pairs, so
\begin{equation}
B\mid D=d,H_0\sim \mathrm{Binomial}(d,1/2).
\label{eq:design-boundary-null-binomial}
\end{equation}
Therefore, for each \(j\in\{0,\ldots,d\}\),
\[
P(B=j\mid D=d,H_0)
=
\binom{d}{j}
\left(\frac12\right)^j
\left(\frac12\right)^{d-j}
=
\binom{d}{j}2^{-d}.
\]
The one-sided alternative places evidence for degradation in large values of \(B\), since many regressions and few improvements imply net loss of accuracy. For a candidate cutoff \(k\), the exact null tail probability is therefore
\begin{equation}
P(B\ge k\mid D=d,H_0)
=
\sum_{j=k}^{d}
P(B=j\mid D=d,H_0)
=
\sum_{j=k}^{d}
\binom{d}{j}2^{-d}.
\label{eq:design-boundary-null-tail}
\end{equation}
At significance level \(\alpha\), the critical value is chosen as the smallest integer cutoff whose null upper tail is at most \(\alpha\):
\begin{equation}
k_\alpha(d)
=
\min
\left\{
    k\in\{0,\ldots,d\}:
    \sum_{j=k}^{d}
    \binom{d}{j}2^{-d}
    \le\alpha
\right\}.
\label{eq:exact-critical-value}
\end{equation}
The one-sided exact McNemar rule rejects when \(B\ge k_\alpha(d)\). If no such \(k\) exists, set \(k_\alpha(d)=d+1\), so rejection is impossible for that \(d\).

At design time, the realised discordance count \(D\) has not yet been observed. Each possible value \(d\in\{0,\ldots,n\}\) therefore defines its own conditional rejection probability \(P(\text{reject}\mid D=d)\). Overall power is the unconditional rejection probability before the data are observed, so the law of total probability gives
\[
P(\text{reject})
=
\sum_{d=0}^{n}
P(D=d)\,P(\text{reject}\mid D=d).
\]
Because \(D\sim \mathrm{Binomial}(n,\rho)\), substituting \(P(D=d)=\binom{n}{d}\rho^d(1-\rho)^{n-d}\) and the exact conditional rejection probability yields
\begin{equation}
\adjustbox{max width=\linewidth}{$\displaystyle \operatorname{Power}(n,\rho,g;\alpha)=\sum_{d=0}^{n}\binom{n}{d}\rho^d(1-\rho)^{n-d}\sum_{j=k_\alpha(d)}^{d}\binom{d}{j}\left(\frac{\rho+g}{2\rho}\right)^j\left(\frac{\rho-g}{2\rho}\right)^{d-j}$}
\label{eq:planning-discordant-m}
\end{equation}
Equation~\eqref{eq:planning-discordant-m} is exact under Assumption~\ref{ass:chapter2-power-model}. For \(\rho=0\), admissibility forces \(g=0\), so power is zero.

For target power \(1-\beta\), define the minimum panel size by
\begin{equation}
    n_{\min}
    =
    \min
    \left\{
        n\in\mathbb{N}:
        \operatorname{Power}(n,\rho,g;\alpha)
        \ge1-\beta
    \right\}.
    \label{eq:minimum-panel-size}
\end{equation}
The threshold \(\alpha\) must match the alerting question being planned, whether nominal or multiplicity-adjusted.

Here \(\rho\) is the probability that a benchmark item changes correctness state between two evaluation times. The historical pilot value \(\hat\rho=137/1199=0.1143\) is the observed discordance rate from a pilot paired comparison on the full 1199-item benchmark: 137 items changed correctness status between the baseline and follow-up runs under the same client-controlled request contract.

Using this pilot discordance estimate, together with \(g=0.05\) and \(\alpha=0.05\), the conditional regression and improvement probabilities are
\[
\frac{\rho+g}{2\rho}=0.7188,
\qquad
\frac{\rho-g}{2\rho}=0.2812.
\]
For the implemented panel size \(n=300\), Equation~\eqref{eq:planning-discordant-m} therefore becomes
\[
\adjustbox{max width=\linewidth}{$\displaystyle \operatorname{Power}(300,0.1143,0.05;0.05)=\sum_{d=0}^{300}\binom{300}{d}(0.1143)^d(0.8857)^{300-d}\sum_{j=k_{0.05}(d)}^{d}\binom{d}{j}(0.7188)^j(0.2812)^{d-j}\approx 0.80$}
\]
Figure~\ref{fig:panel-size-vs-rho} shows how the exact minimum panel size depends on the assumed discordance probability \(\rho\) for 3-, 5-, and 8-percentage-point degradations at nominal \(\alpha=0.05\) and target power \(0.80\). Higher discordance requires larger panels because the same fixed degradation becomes less dominant among the discordant pairs. At the pilot value \(\hat\rho=137/1199\), the exact 80\%-power threshold for \(g=0.05\) is \(n_{\min}=304\). 

The implemented choice \(n=300\) lies just below this cutoff and yields exact power \(0.7955\), which rounds to \(0.80\). The historical choice of 300 followed that rounded value, and the small gap to the formal 80\% threshold became visible only after the later exact post-processing pass.

The implemented monitoring design therefore fixes the panel size at \(n=300\). The remaining question addresses which posts should occupy those 300 positions.

\section{Disagreement-based subset construction}
\label{sec:informative-sampling-disagreement}

With target size fixed at \(n=300\), construction chooses the identities in \(\mathcal{I}_n\). The panel favours posts where models disagree, because those posts are more likely to expose subtle behavioural change. This is close in spirit to query-by-committee sampling~\cite{seung1992query}: when several models disagree on the same item, that item is a plausible candidate for a hard or boundary-near case.

The ensemble contained ten OpenAI and six Gemini models. Coverage was sparse, so the vote summary for post \(i\) uses:
\begin{description}
    \item[\(K_i\)] number of available model votes for post \(i\);
    \item[\(\hat y_i^{(k)}\)] binary vote of model \(k\) on post \(i\);
    \item[\(\hat p_i\)] positive-vote fraction.
\end{description}
It is defined by
\begin{equation}
    \hat p_i
    =
    \frac{1}{K_i}
    \sum_{k=1}^{K_i}\hat y_i^{(k)}.
    \label{eq:positive-vote-fraction}
\end{equation}
If \(\hat p_i=0\) or \(\hat p_i=1\), the available models agree unanimously. Values near \(0.5\) indicate stronger disagreement.

Figure~\ref{fig:vote-share-distribution} shows the realised distribution of \(\hat p_i\) over the 1197 benchmark posts with at least one observed prediction in the eight-run matrix. The mass at \(\hat p_i=0\) and \(\hat p_i=1\) comes from unanimous rows. The interior bars are the mixed-vote rows, and the central bars near \(0.5\) are the most evenly split cases.

The fixed 300-post panel was then obtained by seeded random sampling from two construction-time buckets. In the recorded execution, the high-disagreement bucket contained \(349\) covered rows and the remaining bucket contained \(850\). The sampler drew \(201\) posts without replacement from the high-disagreement bucket and \(99\) from the remaining covered rows, using \texttt{numpy.random.default\_rng(42)} and a final shuffle. This split keeps disagreement enrichment as the dominant signal without treating one observed comparison pass as a perfect oracle of item difficulty: posts outside the high-disagreement bucket may still be hard or boundary-near, but they did not surface as maximally split in that one realised run. Figures~\ref{fig:vote-share-distribution} and~\ref{fig:sensitivity-panel-intuition} visualise the corresponding disagreement structure in the canonical eight-run matrix, where disagreement is densest around \(\hat p_i=0.5\).

\section{Selection bias and monitoring objective}
\label{sec:selection-bias}

This design creates a direct trade-off. Because the monitoring subset was created by disagreement enrichment rather than by probability sampling from \(\mathcal{D}_N\) or from production, its class balance, modality mix, and difficulty profile differ from the full benchmark. The gain is sensitivity: hard boundary-near posts are overrepresented, so local behavioural changes are more likely to appear on repeated paired checks. The cost is that the accuracy level and temporal changes measured on \(\mathcal{D}_n\) describe the panel itself rather than benchmark-wide or production-wide frequencies.

The roles of the two evaluation datasets are therefore distinct:
\begin{enumerate}
    \item \(\mathcal{D}_N\) supports finite full-benchmark calculations on 1199 labelled items.
    \item \(\mathcal{D}_n\) supports repeated paired monitoring on 300 frozen, disagreement-enriched items.
\end{enumerate}

The two datasets serve different roles. The panel supports paired drift detection, and the full benchmark supports deployment ranking and cost-aware selection. An alert on \(\mathcal{D}_n\) triggers a broader evaluation on \(\mathcal{D}_N\).

Under the historical nominal design scenario \((\rho,g,\alpha)=(137/1199,0.05,0.05)\), the exact unconditional power of the implemented 300-item panel rounds to \(0.80\). This validates the implemented panel as an adequate fixed sensitivity set for repeated paired McNemar monitoring on the frozen subset, not as a representative miniature of the full benchmark.
